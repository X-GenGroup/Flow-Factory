# v0.5.0 implementation and release acceptance

v0.5.0 completes the framework's declared TP/SP/Ulysses-CP paths across the current **19 model
adapters and 14 trainers**. The [user guide](../../guidance/parallelism/README.md) describes the
supported layouts; the [implementation reference](../reference/parallelism/README.md) describes
ownership and numerical obligations. This is a scoped support promise, not a measured Cartesian
product of every model, algorithm, precision, backend and topology.

## Implementation checkpoint

The model stack includes canonical packed TP, model-specific CP, algorithm/state composition,
and the SP completion of dual/single streams, inter-block residuals, refiners, text streams and
eligible output heads. Source docstrings describe local ownership; agent routing selects the
relevant contracts and tests without loading the historical investigation archive at startup.

Review the [current model handoff](../../roadmap/handoffs/v0.5-model-closure.md) and
[SP completion record](../../roadmap/handoffs/v0.5-sp-completion.md) for the PR dependency order,
source identities and evidence. P12 remains in progress while these PRs await merge. A merge does
not create a release tag or relabel the original GPU executions to the merge commit.

## Evidence to carry into release

- Preserve independent model output/derivative/update oracles and algorithm objective/lifecycle
  proofs. Reuse unchanged owners with an explicit source-delta review; keep fresh and historical
  receipts distinct. A capability declaration alone is not a test result.
- Exercise changed interactions with purposeful local layouts, usually two GPUs for TP and eight
  for DP2 × TP2 × CP2. Cross-node execution and a full model/backend matrix are not additional
  release gates for this scope.
- Preserve async overlap ownership, logical sample/reward counts, valid gradients and updates.
  Ready-order scheduling need not produce bitwise-identical later trajectories. Exact loaded state,
  the first same-state update and each run's subsequent objective/optimizer checks remain separate
  guarantees. Reward-latency hiding and throughput claims require their own measurements.
- Preserve failed candidates and capacity results alongside successful replacements. Small native
  numerical fixtures establish correctness at their stated geometry; they do not establish
  pretrained convergence or unrestricted memory capacity.

## Compatibility and packaging work after implementation

[P13](../../roadmap/milestones/v0.5.md#p13) owns clean installation, dependency tuples, migration,
examples and built-artifact verification. The ordinary numerical environment is PyTorch 2.10.0,
Diffusers 0.41.0 and Accelerate 1.15.0. Flux3 and Bagel use their separately pinned optional
Diffusers/kernel environments recorded in their [model references](../../guidance/parallelism/models.md).
Do not replace those pins with an untested claim that any development build works.

Exact state continuation requires the same recorded topology and prepared tensor placements.
The new TP runtime identity fingerprints placements as well as global names/shapes. Earlier TP
state checkpoints without that fingerprint require a weights-only restart or explicit migration;
canonical model weight export/loading remains compatible. See
[parameter state](../development/parameter-state.md) for the complete resume contract.

[P14](../../roadmap/milestones/v0.5.md#p14) owns final integration acceptance, version metadata,
release notes, source/package artifacts and the CUDA image. Publish tags only after selecting and
checking their actual historical targets. The proposed `v0.3.0` and `v0.4.0` checkpoints remain
`17e8be7c` and `fbb038e3`; this document does not create either tag. At the 2026-11-08 checkpoint,
the published tags are `v0.1.0` and `v0.2.0`.

No new model feature is planned as a prerequisite after the implementation stack closes.
Concrete compatibility or integration defects discovered during release checks still need fixes.
EP/DeepEP, model-admitted Ring, arbitrary in-flight recovery and topology-changing optimizer
continuation remain separate future work. DMD2 orchestration PR #304 remains independently reviewed.
