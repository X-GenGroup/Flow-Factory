# Native precision on Torch 2.10–2.14

The package floor remains Torch 2.10. This compatibility change preserves each Torch version's
native RMSNorm behavior and repairs the boundaries that surround it. It neither upgrades the
published v0.5.0 image nor changes the meaning of the explicit Wan FP32 attention policy.

## Ownership

| Boundary | Behavior |
|---|---|
| Native RMSNorm | Remains owned by Torch/model code; CUDA autocast promotes it to FP32 from 2.12 |
| Across-head TP RMSNorm | Matches that version's native output dtype, with the existing FP32 statistics and paired-gradient accumulation |
| Explicit FP32 attention | Accepts colocated FP16/BF16/FP32 operands, computes with AMP disabled and returns the incoming query dtype |
| Diffusers 0.42 native CP backward | Re-enters the forward's device, enabled flag, autocast dtype and cache setting before native SDPA recomputation |
| Other attention kernels | Keep existing native behavior; the Torch 2.11 Hopper cuDNN guard remains in effect |

`models/parallelism/autocast.py` is the bounded compatibility owner. `ModelPreparation` installs
its native CP wrapper after validating all canonical/variant roots and before any CP forward.
State is stored on each autograd context, so two outstanding forwards with different autocast
settings do not overwrite one another. No new parameter, state-dict key or checkpoint schema is
introduced. The TP helper affects the existing Wan T2V/I2V and LTX2 across-head styles; it does
not replace other model families' normalization implementations.

Remove the Diffusers callback backport after an upstream release passes the same enabled,
disabled and multiple-outstanding-graph derivative controls. It deliberately applies only to
the measured 0.42 release line. Native transports, distributed groups and SDPA kernels are not
copied into the framework. Newer dependency versions remain advisory-only, not rejected.

## Environment and selected witnesses

Use isolated Python 3.12 environments with Torch 2.10.0+cu128, 2.11.0+cu128, 2.12.1+cu126,
2.13.0+cu126 and 2.14.1+cu126, Accelerate 1.15.0 and Diffusers 0.42.1. The qualification host
has eight local CUDA devices reporting capability 9.0, with driver 570.172.08. Keep model
fixtures, random seeds and test thresholds unchanged between environments. Binary dependency
versions are recorded with each evidence receipt; the CUDA-wheel differences preclude attributing
performance differences solely to Torch.

| Witness | Resources | Correctness guarantee |
|---|---|---|
| Mixed explicit FP32 attention and native CP replay | CPU + one GPU | Exact output and all Q/K/V derivatives; invalid inputs; backward under opposite AMP; outstanding graphs |
| Native versus TP RMSNorm | TP2 | BF16/FP16, AMP on/off, paired/unpaired norms and checkpoint replay: dtype, output, input and parameter gradients |
| Paired norm cancellation | Gloo2 | Existing independent FP64, collective-count and cleanup controls |
| Wan SFT state/resume | DP2 × CP2 | FP32 cross-attention, exact load/RNG/EMA and continued optimizer updates |
| Kontext Guard full tuning | DP2 × TP2 × CP2, SP on | Rollout/training agreement, gradients/updates, ordered reward overlap and lifecycle |
| Flux DPPO LoRA | DP2 × TP2 × CP2 | Alternate parameter ownership, ready-order overlap and continuation |
| LTX 2.3 I2AV GRPO | DP2 × TP2 × CP2, SP on | Second across-head norm consumer, conditioned audio/video, native lifecycle |

The five-version core consists of CPU contracts, CUDA replay, TP norm parity and the three
Wan/Kontext/Flux trainer scenarios. The canonical diff-selected plan additionally retains the
LTX consumer, native Ring, physical CP roots/transport meshes, backend preparation and state
witnesses. Extra cases need not be multiplied across every dependency tuple. Exact commands,
JUnit/rank records, environment versions, source SHA and artifact hashes are attached to the PR;
only completed runs constitute evidence.

Tests compare within a version and retain existing model gradient/update thresholds. The
independent FP64 attention oracle recognizes genuine FP32 forward operands and includes the
existing FastF32 conversion-error terms for them. BF16-exact inputs retain zero conversion error;
no observed gradient determines its budget. Zero/half/double and single-element corruption
controls must still fail. Successful startup or
finite loss alone is insufficient. These small native-model fixtures establish functional and
numerical compatibility, not pretrained convergence or a performance improvement. Cross-version
bitwise equality and cross-node execution are not qualification requirements here.

To reproduce, run the canonical planner and the selected commands in the desired environment:

```bash
python3 scripts/validation_plan.py generate --base origin/main --head HEAD --output plan.json
# Execute selected CPU/GPU commands, preserving their source and environment identities.
python3 scripts/validate_validation_plan.py --help
```
