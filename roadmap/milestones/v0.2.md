## Current capability boundary

The [merged TP implementation notes](https://github.com/X-GenGroup/Flow-Factory/blob/55dcd69433deb11159d5c03c22689518ce6f315e/.agents/knowledge/topics/tensor_parallel.md)
and PR body are starting evidence, not interchangeable claims of support.

| Area | Current boundary / remaining work |
|---|---|
| Backend and mesh | TP requires FSDP2 with at least two FSDP shards. A TP=2 production path therefore needs at least four ranks; primitive parity tests can use two. CP/EP are not implemented. |
| SP defaults | Adapter-specific: on for SD3.5 and Wan T2V, off elsewhere; explicit SP requires a plan and divisible token lengths. SP reuses the TP group. |
| Real-weight evidence | SD3.5-Medium and Wan2.1-T2V-14B have TP+SP runs; Qwen-Image-2.1 has TP-only runs. Other plans have differing CPU/plan coverage; do not promote them all to real-weight-verified support. |
| Qwen-Image-2.1 | Explicit SP rejects odd prompt-prefix lengths. Separately, the merged notes still report an unexplained real-training forward/gradient difference, while later PR results report successful TP runs. P03 must reconcile these with revision-specific numerical evidence; a successful run alone does not close the parity question. |
| Loading and capacity | H3 TP materializes too much before FSDP sharding for the measured 80 GB cards. Use FSDP2 without TP there; evaluate a bounded meta/sharded-loading follow-up under P06 rather than claiming H3 TP validation. |
| State | Model-only and basic model/optimizer round trips exist. FSDP exact-state continuation with EMA/reference/algorithm snapshots is explicitly rejected; P07 closes the intended state combinations. |
| Early rejections | Unsupported plans/backends, Muon with TP, `subgroup_tile`, SP with `diffusers_cache`, CPU-efficient FSDP loading and incompatible head counts remain explicit restrictions. |
| Reward and decode | TP peers split scoring and agree on results; decode remains duplicated. Worker CUDA-device selection from #274 and collective ordering must survive lifecycle cleanup. Decode sharing is a separate measured optimization, not an implicit refactor. |
