## P23: model-specific SFT conditioning dropout

- **Status:** done (numeric policies for all 19 built-in adapters and qualified native recipes)
- **Depends on:** [P14](v0.5.md#p14)
- **User guide:** [SFT condition dropout](../../guidance/training/sft-conditioning.md)
- **Delivery:** stacked changes cover image policies, AV policies, packed-model recipes, then both SFT input paths, onboarding and validation. The P23a–P23d anchors below identify acceptance areas within this delivery.
- **Release boundary:** qualify the 19 built-in adapter IDs for v0.6.x before [EP model admission](v0.6-v0.7.md#p15b).

<a id="p23a"></a>
### User contract

```yaml
train:
  trainer_type: sft
  condition_dropout: 0.1
```

| Value | Training behavior |
| --- | --- |
| Omitted | Apply the numeric policy at `0.1`. |
| `0` | Use the original conditions. Preserve legacy checkpoint compatibility and skip preparation of alternatives. |
| Number `p` in `(0, 1]` | For a record with eligible conditions, keep all of them with probability `1-p`. With probability `p`, draw a nonempty drop mask using the model's policy for this task and its present input segments. At `1` every eligible record loses at least one condition. A record without eligible conditions keeps its inputs. |
| `native` | Use the stage- and variant-specific published training recipe directly, including its probability of keeping everything, segment eligibility and dependence between draws. With multiple task types, resolve the recipe per record. |

Reject booleans, nonfinite/out-of-range numbers and unknown strings at configuration parsing.
At admission, diagnose an unavailable policy with the checkpoint, task, requested mode and
supported modes. A mixed-source `native` run requires a verified recipe for every active task.
Apply dropout to SFT training inputs only. Compute one ordinary SFT prediction for the selected
condition at each sampled time. Keep the demonstration target, active loss regions and clocks
under their existing owners.

### How to choose and scale a policy

1. Look for the authors' training sampler **and effective launch configuration** for the matching
   checkpoint, training stage and task. Record the revision, eligible segments, protection of
   supervised targets, joint distribution and actual empty representation. This evidence can
   qualify `native` once the implementation reproduces it.
2. Where only inference is public, compare the inputs to each classifier-free guidance (CFG)
   forward before scale mixing. Use this to define and qualify a numerical policy. Inference
   establishes the branch semantics. Training rates need their own source.
3. For a guidance-distilled checkpoint without an unconditional forward, document any proposed
   caption or modality dropout as a Flow-Factory training augmentation. Qualify a legal absent
   input on the same checkpoint and preserve its embedded guidance or other required controls.

For a known recipe with mask distribution `Q`, numeric mode uses its distribution **conditioned
on a nonempty mask** for the second draw. Thus `p` controls a record-level event even when the
native sampler makes several independent draws. Derive this distribution for the eligible
segments in the actual record. For independent segments, an exact implementation can sample the
first dropped segment with weights `q_i * product(1-q_j for j<i)`, then draw subsequent segments
at their original rates. This avoids enumerating all subsets or retrying until a rare event fires.
Declare an explicit numeric policy for any supported task whose native recipe has zero drop mass.

### Implementation and ownership

- **Configuration and sampling.** Resolve a typed SFT policy from the adapter and effective
  checkpoint/task. The adapter describes eligible logical inputs, their probabilities and the
  method that constructs each sampled input. SFT owns RNG and applies the selected mask once
  per record and data epoch across all timestep terms. Key deterministic draws on seed, epoch,
  record ID and stable event/segment identifiers. A stochastic source must be independent of
  target encoding, time and forward noise. TP/SP/CP peers processing the same record must agree.
- **Condition construction.** Reuse the adapter's projection, encoders, condition preparer and
  output binding. Construct a temporary condition view for the selected mask, including IDs,
  masks, pooled embeddings, reference ordering and KV layout. Keep target media and provenance
  immutable. Multiple input streams can share a policy when their task and numerical semantics
  match. [SFT trainer](../../src/flow_factory/trainers/offline/sft.py) · [condition state](../../src/flow_factory/models/condition_state.py)
- **Cached input.** Keep random choices outside the positive cache. Share deterministic empty
  text for identical encoder/template/precision settings. Key a multimodal alternate encoding
  by its retained media content, order and presentation. For packed, independently droppable
  segments, reuse encoder outputs or immutable prefixes where valid and assemble the selected
  context at runtime. When selection changes joint attention, recompute the affected context
  through its owner. Avoid materializing every possible mask. Coordinate cache misses across
  ranks and preserve deferred encoder loading on reusable cache hits.
- **On-demand input.** Before P23 both [config parsing](../../src/flow_factory/hparams/args.py#L324)
  and the [offline loader](../../src/flow_factory/data_utils/offline_train_data.py#L162) required
  preprocessing. Implement a raw SFT condition source using the [V2 projection](../../src/flow_factory/data_utils/offline_condition_cache.py).
  Under `data.enable_preprocess: false`, CPU workers decode inputs and targets separately. The
  training rank selects a mask before encoding, loads frozen encoders through the coordinator
  and builds only the requested condition. Reuse the finite sampler, stable IDs, multi-source
  boundaries and output codec. Scope this raw path to SFT, including `p=0`.
- **Continuation and diagnostics.** Bind enabled mode, probability, resolved policy revision
  and effective recipe to checkpoint execution identity. Count eligible records, realized
  record-level drops and per-branch or per-segment drops by task, counting each logical sample
  once across model-parallel peers. Keep cache construction and evaluation separate from training draws.

### Future model admission

For every new adapter or checkpoint specialization, the `ff-new-model` design review records a
row **per supported task** (for example T2I and ordered I2I, or T2VA and Ref2VA). Capture:

| Required entry | What the contributor provides |
| --- | --- |
| Applicability | Adapter ID, checkpoint/variant, task and SFT capability. Record online-only modes as outside SFT scope. |
| Policy and provenance | Numeric behavior, eligible units and joint/independent decisions, protected inputs/targets, and a pinned upstream recipe or inference branch. Label framework-defined augmentations. State whether `native` is available and why. |
| Realization | Map each branch to raw inputs, encoded representations, required media, positions and masks. Identify reusable cached values and any branch-specific work in both input paths. |
| Evidence | Show keep/drop branch parity on fixed inputs, target preservation, cached/raw agreement and the appropriate negative admission test. Independent visual segments and ordered references require their own witnesses. |

Record this disposition during model design. The adapter must expose the declared policy for each SFT task and the registry test must exercise it.
Publish qualified modes in the user support table and keep the [model guide](../../docs/development/new-model.md)
and [agent checklist](../../.agents/skills/ff-new-model/references/integration.md) linked to the contract.

### Validation record

- The image controls compare SD3.5 sequence and pooled embeddings to direct empty text encoding and compare Klein Base velocity to its unmixed CFG arm with two ordered references. Qwen editing controls change the reference order and check that the absent instruction's embeddings change with it.
- The AV controls exercise H3 T2VA, FL2VA and Ref2VA with the released processor and reduced native weights. Each preserves the generated AV rows and has a nonzero context gradient. Wan first/last-frame tests and LTX connector and masking tests cover the other AV presentations.
- Two-rank FSDP2 tests compare BAGEL and SenseNova with their native, unsharded prefixes for the same mask. Separate public-entry CPU tests compare cached and on-demand optimization for both families.
- Two independent Klein Base FSDP2 editing runs compare cached and on-demand conditioning, target, noised latent, velocity, loss, gradients and the optimizer delta. A four-rank Wan DP2 × CP2 continuation uses different drop decisions across data replicas and checks exact subsequent masks, losses, gradients and weights after restore.

The [SFT guide](../../guidance/training/sft-conditioning.md) lists the supported presentations, cache behavior and migration setting for old checkpoints.
