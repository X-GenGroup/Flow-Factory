# v0.5.x–v0.6: ART, differentiable rewards and component execution

Reviewed against main `29593921` on 2026-11-11. Existing parallel backends remain the stable
foundation. Algorithm work precedes EP: ART is an additive v0.5.x feature; v0.6 introduces
backpropagation through a frozen reward model and the component policies needed to run it.
The [design checkpoint](../design/differentiable-rewards.md) defines ownership and open decisions.
P18–P21 are new stable IDs; P00–P17 retain their historical meaning.

## P18: DiffusionART in v0.5.x

- **Status:** done (algorithm integration and functional qualification)
- **Depends on:** [P14](v0.5.md#p14), [P15a](v0.6-v0.7.md#p15a)
- **Coordination:** [#377](https://github.com/X-GenGroup/Flow-Factory/pull/377) merged as
  [`29593921`](https://github.com/X-GenGroup/Flow-Factory/commit/29593921e86382f7a1fefe9b859b40db82f17ac5).
  Its validation records retain their original tested-source identities. This roadmap does not
  relabel those receipts as new GPU runs.
- **Release boundary:** next available v0.5.x source patch after review; assign its exact tag at release
- **Outcome/scope:** direct `BaseTrainer` implementation using generation/runtime reward, complete
  rank-local prompt groups, stored Euler ODE states and velocities, normalized endpoint covariance,
  configurable sequential updates over disjoint partitions and a directional reference-transition mask.
  Reuse sampler identity, reward reduction, packed-batch ordering, accumulation, optimizer and
  drained-boundary checkpoint owners. No differentiable reward is needed for ART.
- **Algorithm contract:** `auto` resolves to `group_contiguous` (`rank_local` alias); complete
  endpoint/reward groups and stored Euler ODE trajectories preserve the objective's inputs.
  Update count and ordinary-path inner epochs are configurable through the shared optimizer
  geometry. Reward reduction and `global_std` use the existing framework semantics.
- **Official/default recipe:** FP32 trajectory storage, one inner epoch and two complete update
  windows are recipe choices, not algorithm admission restrictions. Lower storage precision
  must retain its declared replay tolerance. Shared overlap admission still requires one inner
  epoch and group-local reward statistics, with complete-group readiness and frozen anchors.
  Joint audio/video and ordinary/ordered/ready overlap are implemented and covered by selected
  LTX2/H3 DDP2 checks. Use the [ART guide](../../guidance/training/art.md#support-boundary)
  for admission conditions; this does not promise every model/backend/algorithm combination.
- **Acceptance:** independent objective/gradient reference, constant signals, mask direction,
  complete-group validation, frozen anchors, configurable update/inner-epoch geometry, the
  default two-update recipe, two acquisition cycles,
  native image LoRA/DDP continuation and native video full/FSDP2 TP/SP/CP derivative/update controls.
  These controls are recorded in [#377](https://github.com/X-GenGroup/Flow-Factory/pull/377):
  FLUX DDP2 ART schedules/continuation, Wan FSDP2 TP/SP with CP1/CP2, joint AV overlap,
  and FLUX FSDP2 DPPO sparse/reversed replay. The selected cases fit within eight local GPUs;
  unchanged evidence is reused at its original identity.
- **Shared baseline:** #377 also merged `scheduler.replay_steps`, transition retention/index
  mapping and unconditional cross-configuration admission. Reuse the
  [sampling contract](../../guidance/training/sampling.md); terminal-state re-noising retains
  the existing `TimeSampler` controls.
- **Experiment follow-through:** the pinned
  [SD3.5/PickScore recipe](../../examples/art/lora/sd3_5/pickscore_8gpu.yaml) and an eight-GPU
  pretrained run are recorded in #377. At merge, training was ongoing; final evaluation and
  reproduction of the authors' quality conclusions were not established. Preserve that run
  as its own source/config identity, including its earlier 128-token forwarding versus the
  merged recipe's native 256-token default. Record final curves, samples and conclusions
  separately; do not treat them as final-source correctness evidence or block P19a on them.
- **Tag gate:** merged source, completed selected evidence, version/changelog and installation
  identities reviewed together. Publication is still pending; implementation completion does not
  imply a new tag, Release or image. Preserve all historical tags.

## P19: differentiable feedback and ReFL

- **Status:** planned
- **Depends on:** [P18](#p18)
- **Coordination:** unclaimed
- **Release boundary:** prerequisite for v0.6.0
- **Outcome:** a reward model may be frozen while retaining derivatives with respect to its input.
  The ordinary detached asynchronous reward path stays intact; a typed optimization-stage feedback
  path owns the differentiable tensor, loss sign/scaling and optional input VJP.

<a id="p19a"></a>
### P19a: reward derivative contract

- **Status:** in_progress on `feat/p19a-differentiable-reward`; awaiting review
- **Depends on:** [P18](#p18)
- **Coordination:** [#381](https://github.com/X-GenGroup/Flow-Factory/pull/381)
- **Release boundary:** prerequisite for v0.6.0
- **Scope:** declare input-gradient support separately from `requires_grad` on weights; implement
  one real scorer with tensor-only resize/crop/normalization and explicit higher-is-better semantics.
  Admit generation plus differentiable feedback through the authoritative execution contract.
  Reward batch independence, dtype, device and output shape are explicit; remote/PIL-only scorers
  fail before execution. No hidden `feedback=none` shortcut through the existing buffer.
- **Implementation:** model-owned `RewardGradientCapability`, optimization-stage feedback mode,
  source-aware pointwise dispatch and image PickScore input gradients. See the
  [reward guide](../../guidance/training/rewards.md#input-gradient-capabilities).
- **Acceptance:** finite-difference/autograd controls, pixel derivatives reaching the caller,
  no scorer parameter gradients/optimizer membership, unchanged ordinary reward outputs, no
  silent detach and meaningful errors for unsupported rewards. Audit every execution-contract consumer.

<a id="p19b"></a>
### P19b: model-complete ReFL program

- **Status:** in_progress on `feat/p19b-refl`; awaiting review
- **Depends on:** [P19a](#p19a)
- **Coordination:** #382 plus `feat/p19b-refl-all-models`, stacked on #381
- **Release boundary:** prerequisite for v0.6.0
- **Implementation:** all 19 registered adapters expose native differentiable image, video or
  audiovisual decoding. Stored component sigmas, model-owned velocity direction, fixed condition
  tokens and generation autocast are preserved. Source-aware reward dispatch selects compatible
  media per scorer. PickScore supports image/video gradients. Optimizer and state owners are reused.
  The [ReFL guide](../../guidance/training/refl.md) records the flow-matching/PickScore adaptation.
- **Scope:** no-grad prefix, one selected differentiable denoising/clean-prediction stage, native
  latent decode, frozen differentiable reward and policy update. Explicitly specify flow-matching
  adaptation, timestep convention, reward loss and optional pretraining regularizer; do not call
  every one-step reward gradient recipe an exact paper reproduction.
- **Acceptance:** nonzero reward-to-policy gradient, finite-difference reference on a tiny native
  model, prefix/scorer frozen-state isolation, two acquisition cycles and drained continuation.
  Validate two native acquisition/update cycles for every registered adapter, then combine
  joint audiovisual gradients and TP/SP/CP/FSDP2 in one eight-GPU LTX2 I2AV case. Reuse the
  SD3.5 continuation and FLUX.1 gradient oracles. Record the real reward revision and video
  gradient evidence. Decoder/reward replication remains the initial component policy.

## P20: component execution policy

- **Status:** planned
- **Depends on:** [P19](#p19)
- **Coordination:** unclaimed
- **Release boundary:** prerequisite for v0.6.0
- **Outcome:** model, reward and preprocessing components use explicit execution policies without
  equating frozen parameters with disabled input gradients. Reuse `ComponentRuntime` and loading/
  preparation owners. User policy describes placement and precision; algorithms declare derivative
  needs. Shared physical roots are prepared once and conflicting policies fail early.

<a id="p20a"></a>
### P20a: resolve policy without changing defaults

- **Status:** planned
- **Depends on:** [P19b](#p19b)
- **Coordination:** unclaimed
- **Release boundary:** prerequisite for v0.6.0
- **Scope:** replicated versus FSDP2 placement, existing mesh-group references, offload/loading
  preferences and precision. Resolve per-phase trainable/frozen-input-grad/no-grad requirements.
  Defaults remain the current replicated auxiliary components and existing policy backend.
- **Acceptance:** typed configuration and alias/conflict checks, one physical owner, stable cache/
  checkpoint identity, existing DDP/ZeRO-2/FSDP2 recipes unchanged. No new implicit mesh multiplier.

<a id="p20b"></a>
### P20b: FSDP2 for reward and differentiable decoder

- **Status:** planned
- **Depends on:** [P20a](#p20a)
- **Coordination:** unclaimed
- **Release boundary:** prerequisite for v0.6.0
- **Scope:** prepare supported reward/decoder roots; route `decode`, `get_*_features` and similar
  entries through an unsharding-aware forward boundary. Backward may all-gather frozen weights to
  compute input derivatives without allocating optimizer state. Synchronize stage/group ordering.
- **Acceptance:** two-GPU replicated versus sharded output/input-gradient/policy-update equality,
  recomputation/offload behavior, bounded memory over repeated cycles and continuation. Include an
  intentional detach negative control. No per-request thread may initiate unordered collectives.

<a id="p20c"></a>
### P20c: preprocessing placement and cache coordination

- **Status:** planned
- **Depends on:** [P20b](#p20b)
- **Coordination:** unclaimed
- **Release boundary:** prerequisite for v0.6.0
- **Scope:** share the placement mechanism with no-grad text/image encoders. Schedule rank-wide
  cache agreement, empty requests, tails and ownership transitions; avoid divergent collectives
  when only some ranks hit cache. Frozen replicated modules need not be wrapped in DDP.
- **Acceptance:** mixed cache hit/miss, variable batch tails, empty local work, deterministic output
  identity and lifecycle cleanup. Two ranks normally suffice; combine with four/eight ranks only
  when policy TP/CP changes the relevant scheduling or reduction boundary.

<a id="p21a"></a>
### P21a: explicit truncated derivative program

- **Status:** planned
- **Depends on:** [P19b](#p19b), [P20b](#p20b)
- **Coordination:** unclaimed
- **Release boundary:** prerequisite for v0.6.0
- **Scope:** implement the paper's selected denoising steps and truncation semantics. Detach the
  denoiser's state input where specified while retaining the direct scheduler state path; do not
  detach the entire scheduler update. Start with an explicitly supported Euler flow solver.
  Other scheduler histories require a separate derivative contract and reference.
- **Acceptance:** independent short unrolled reference; selected/unselected timestep derivatives,
  retained state path, reward/policy gradient direction and exact continuation. A deliberately
  detached scheduler path must fail. Combine a second model with these checks instead of repeating
  all algorithms over all models/backends.

<a id="p21b"></a>
### P21b: optional staged VJP for memory

- **Status:** planned
- **Depends on:** [P21a](#p21a)
- **Coordination:** unclaimed
- **Release boundary:** optional optimization; does not block v0.6.0
- **Scope:** only after P21a, split reward/decoder/policy backward by explicit input VJPs where
  profitable. Preserve model version, RNG, precision and preprocessing across rematerialization.
- **Acceptance:** match the end-to-end reference's input and parameter gradients; measure peak
  memory and throughput for a stated workload. No requirement for a universal speedup.
