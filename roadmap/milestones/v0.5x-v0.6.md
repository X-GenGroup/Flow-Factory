# v0.5.x–v0.6: ART, differentiable rewards and component execution

The v0.6 training stack is merged at `d09f38b7`. It combines DiffusionART, differentiable
reward and ReFL paths, component execution policies, and the DRaFT-K and DRTune algorithms.
Expert parallelism follows v0.6.
The [design checkpoint](../design/differentiable-rewards.md) defines ownership and open decisions.
P18–P22 are stable IDs. P19–P22 define the [v0.6.0 release gate](#v06-release-gate).

## Delivery sequence

| Order | PR boundary | Depends on | Required result |
|---|---|---|---|
| 1 | P18: DiffusionART (merged #377) | P14, P15a | Complete prompt groups, configurable update schedules, numerical controls and representative distributed lifecycle |
| 2 | P19a: differentiable feedback contract (merged #381) | P18 | Typed differentiable reward capability, tensor-only preprocessing and one real frozen scorer |

Use an independent worktree per PR and native Stack PR relationships for dependent changes.
Each PR must stand as a stable change with its own relevant checks; the user reviews and merges.
P21b is optional and does not block v0.6. Do not introduce a general execution graph before an
implemented algorithm needs one, or turn this work into an Accelerate replacement.

## P18: DiffusionART in v0.5.x

- **Status:** done (algorithm integration and functional qualification)
- **Depends on:** [P14](v0.5.md#p14), [P15a](v0.6-v0.7.md#p15a)
- **Coordination:** [#377](https://github.com/X-GenGroup/Flow-Factory/pull/377) merged as
  [`29593921`](https://github.com/X-GenGroup/Flow-Factory/commit/29593921e86382f7a1fefe9b859b40db82f17ac5).
  Its validation records retain their original tested-source identities. This roadmap does not
  relabel those receipts as new GPU runs.
- **Release boundary:** additive v0.5.x source work included in the v0.6.0 distribution
- **Outcome/scope:** direct `BaseTrainer` implementation using generation/runtime reward, complete
  rank-local prompt groups, stored Euler ODE states and velocities, normalized endpoint covariance,
  configurable sequential updates over disjoint partitions and a directional reference-transition mask.
  Reuse sampler identity, reward reduction, packed-batch ordering, accumulation, optimizer and
  drained-boundary checkpoint owners. No differentiable reward is needed for ART.
- **Algorithm contract:** `auto` resolves to `group_contiguous` (`rank_local` alias); complete
  endpoint/reward groups and stored Euler ODE trajectories preserve the objective's inputs.
  Update count and ordinary-path inner epochs are configurable through the shared optimizer
  geometry. Reward reduction and `global_std` use the existing framework semantics.
- **Official/default recipe:** FP32 trajectory storage, one inner epoch and two complete update
  windows are recipe choices, not algorithm admission restrictions. Lower storage precision
  must retain its declared replay tolerance. Shared overlap admission still requires one inner
  epoch and group-local reward statistics, with complete-group readiness and frozen anchors.
  Joint audio/video and ordinary/ordered/ready overlap are implemented and covered by selected
  LTX2/H3 DDP2 checks. Use the [ART guide](../../guidance/training/art.md#support-boundary)
  for admission conditions; this does not promise every model/backend/algorithm combination.
- **Acceptance:** independent objective/gradient reference, constant signals, mask direction,
  complete-group validation, frozen anchors, configurable update/inner-epoch geometry, the
  default two-update recipe, two acquisition cycles,
  native image LoRA/DDP continuation and native video full/FSDP2 TP/SP/CP derivative/update controls.
  These controls are recorded in [#377](https://github.com/X-GenGroup/Flow-Factory/pull/377):
  FLUX DDP2 ART schedules/continuation, Wan FSDP2 TP/SP with CP1/CP2, joint AV overlap,
  and FLUX FSDP2 DPPO sparse/reversed replay. The selected cases fit within eight local GPUs;
  unchanged evidence is reused at its original identity.
- **Shared baseline:** #377 also merged `scheduler.replay_steps`, transition retention/index
  mapping and unconditional cross-configuration admission. Reuse the
  [sampling contract](../../guidance/training/sampling.md); terminal-state re-noising retains
  the existing `TimeSampler` controls.
- **Experiment follow-through:** the pinned
  [SD3.5/PickScore recipe](../../examples/art/lora/sd3_5/pickscore_8gpu.yaml) and an eight-GPU
  pretrained run are recorded in #377. At merge, training was ongoing; final evaluation and
  reproduction of the authors' quality conclusions were not established. Preserve that run
  as its own source/config identity, including its earlier 128-token forwarding versus the
  merged recipe's native 256-token default. Record final curves, samples and conclusions
  separately; do not treat them as final-source correctness evidence or block P19a on them.
- **Tag gate:** merged source, completed selected evidence, version/changelog and installation
  identities reviewed together. Publication is still pending; implementation completion does not
  imply a new tag, Release or image. Preserve all historical tags.

<a id="p19a"></a>
### P19a: reward derivative contract

- **Status:** done
- **Depends on:** [P18](#p18)
- **Coordination:** [#381](https://github.com/X-GenGroup/Flow-Factory/pull/381) merged as
  `694c5d14`
- **Release boundary:** prerequisite for v0.6.0
- **Scope:** declare input-gradient support separately from `requires_grad` on weights; implement
  one real scorer with tensor-only resize/crop/normalization and explicit higher-is-better semantics.
  Admit generation plus differentiable feedback through the authoritative execution contract.
  Reward batch independence, dtype, device and output shape are explicit; remote/PIL-only scorers
  fail before execution. No hidden `feedback=none` shortcut through the existing buffer.
- **Implementation:** model-owned `RewardGradientCapability`, optimization-stage feedback mode,
  source-aware pointwise dispatch and PickScore input gradients. The
  [reward guide](../../guidance/training/rewards.md#input-gradient-capabilities) documents the
  current image and video support.
- **Acceptance:** finite-difference/autograd controls, pixel derivatives reaching the caller,
  no scorer parameter gradients/optimizer membership, unchanged ordinary reward outputs, no
  silent detach and meaningful errors for unsupported rewards. Audit every execution-contract consumer.

<a id="p19b"></a>
### P19b: model-complete ReFL program

- **Status:** done
- **Depends on:** [P19a](#p19a)
- **Coordination:** [#382](https://github.com/X-GenGroup/Flow-Factory/pull/382) merged as
  `49f4b272`. The [evidence run](https://github.com/X-GenGroup/Flow-Factory/actions/runs/43370943722)
  records the qualified PR source.
- **Release boundary:** prerequisite for v0.6.0
- **Implementation:** all 19 registered adapters expose native differentiable image, video or
  audiovisual decoding. Stored component sigmas, model-owned velocity direction, fixed condition
  tokens and generation autocast are preserved. Source-aware reward dispatch selects compatible
  media per scorer. PickScore supports image/video gradients. Optimizer and state owners are reused.
  The [ReFL guide](../../guidance/training/refl.md) records the flow-matching/PickScore adaptation.
- **Scope:** no-grad prefix, one selected differentiable denoising/clean-prediction stage, native
  latent decode, frozen differentiable reward and policy update. Explicitly specify flow-matching
  adaptation, timestep convention, reward loss and optional pretraining regularizer; do not call
  every one-step reward gradient recipe an exact paper reproduction.
- **Acceptance:** nonzero reward-to-policy gradient, finite-difference reference on a tiny native
  model, prefix/scorer frozen-state isolation, two acquisition cycles and drained continuation.
  Validate two native acquisition/update cycles for every registered adapter, then combine
  joint audiovisual gradients and TP/SP/CP/FSDP2 in one eight-GPU LTX2 I2AV case. Reuse the
  SD3.5 continuation and FLUX.1 gradient oracles. Record the real reward revision and video
  gradient evidence. Wan I2V FSDP2 checks shared replay coordinates and updates to both denoisers.
  LTX2/H3 DDP2 video-only objectives additionally qualify dynamically unused
  output heads and composed guidance. Decoder/reward replication remains the initial component policy.

## P20: component execution policy

- **Status:** done
- **Depends on:** [P19](#p19)
- **Coordination:** merged in #385–#387
- **Release boundary:** prerequisite for v0.6.0
- **Outcome:** model, reward and preprocessing components use explicit execution policies without

<a id="p21a"></a>
### P21a: DRaFT-K through the final sampling steps

- **Status:** done
- **PR:** [#389](https://github.com/X-GenGroup/Flow-Factory/pull/389), merged as `2665f982`
- **Depends on:** [P19b](#p19b), [P20b](#p20b)
- **Release boundary:** prerequisite for v0.6.0
- **Scope:** adapt [DRaFT-K](https://arxiv.org/html/2309.17400#S4) to Euler flow matching.
  Run the first `T - K` sampling transitions without gradients and start from the detached
  suffix entry state. Unroll the last `K` contiguous transitions using the live state returned
  by each model/scheduler step. Evaluate the existing differentiable reward on the native
  decoded endpoint. Use one policy version for the prefix and suffix. Reuse the P19 feedback,
  accumulation and logging owners. Keep the cut point and schedule reproducible across resume.
  `K = T` represents full-chain differentiation.
  Additional solvers require their own schedule, state and derivative checks.
- **Acceptance:** compare endpoint values with a native no-grad rollout at fixed inputs and
  weights. Compare policy gradients and probe the suffix-entry derivative against an independent
  FP32 Euler unroll for `K = 1`, `1 < K < T` and `K = T` on a short schedule. Assert that the
  training graph stops at the prefix and that detaching a suffix state or substituting a saved next state
  fails the gradient comparison. Verify a native update, frozen auxiliary isolation and
  next-update continuation. Select a second model or parallel layout for a distinct runtime
  obligation.

### Baseline combinations and CUDA gates

| Algorithm and model | Policy backend | Auxiliary execution |
| --- | --- | --- |
| GRPO and ART on their existing recipes | Existing qualified backends | Existing reward and preprocessing behavior |
| ReFL on existing image, video and AV adapters | Existing qualified ReFL layouts | Replicated by default |
| ReFL on SD3.5 with one training source | Data-only FSDP2 | Opt-in sharded text encoders, frozen VAE and synchronous PickScore |
| DRaFT-K on SD3.5 with Euler ODE | Local, data-only DDP or FSDP2 | Replicated VAE and synchronous differentiable scorer |

The [sharded ReFL recipe](../../examples/refl/lora/sd3_5/pickscore_fsdp2.yaml)
exercises all three auxiliary stages in one run. Initial CPU evidence covers the
native frozen VAE and CLIP input derivatives, preprocessing tails and empty
shards, and DRaFT-K endpoint and continuation. Record exact-head results for
the selected baseline GPU cases.

1. **Two-rank FSDP2 SD3.5 ReFL.** The catalog has a decoder/scorer case for P20b
   and a joint encoder/decoder/scorer case for P20c. Compare replicated and sharded auxiliaries at
   matched policy state and logical samples. Check scores, input and policy
   gradients and updates at the shared initial state. Verify exact restored model
   and optimizer state, then compare the next forward and CUDA update numerically.
   Use the same run to
   verify cache hits and misses, encoder CPU offload and stable peak memory
   across repeated updates. Use real PickScore for scorer qualification.
2. **Two-rank DRaFT-K.** Run the cataloged SD3.5 DDP and data-only FSDP2
   cases with replicated auxiliaries. Retain native endpoint parity and
   compare suffix updates at a common state. Exercise activation checkpointing.
3. **Representative parallel policy regression.** The SD3.5 inference edit
   retains the native DP2 × TP2/SP × CP2 replay lifecycle case. Existing ReFL
   replicated layouts retain their [P19b evidence](https://github.com/X-GenGroup/Flow-Factory/actions/runs/43370943722)
   at its original tested commit. Ordinary reward and backward regressions for
   ART and GRPO remain in the CPU suite. Changes to the ReFL objective or
   additional SD3.5 adapter boundaries retain their wider GPU routes.

- **Status:** done
- **Depends on:** [P21a](#p21a), [P21c](#p21c)
- **Coordination:** [P22a](https://github.com/X-GenGroup/Flow-Factory/pull/392) and
  [P22b](https://github.com/X-GenGroup/Flow-Factory/pull/393).
- **Release boundary:** P22a and P22b are required for v0.6.0.
- **Implementation priority:** complete P22 before starting P15b–P15f runtime work.
  The EP dependency graph continues to track its technical prerequisites.
- **Scope:** adapt the stop-gradient estimator in
  [Deep Reward Supervisions for Tuning Text-to-Image Diffusion Models](https://www.ecva.net/papers/eccv_2024/papers_ECCV/papers/10922.pdf),
  §3.2 and Algorithm 1, to SD3.5 Euler ODE. Use the
  [reward-gradient design](../design/differentiable-rewards.md#drtune) for ownership,
  trajectory selection and comparison with ReFL and DRaFT-K.
- **Acceptance:** two scoped implementation PRs with independent derivative
  references and selected GPU evidence. Publish the supported flow-matching
  recipe and its measured activation-memory profile with the qualified algorithm.

- **Status:** done

## v0.6.0 release gate

The [P21c baseline](#p21c) and both [DRTune stages](#p22) are merged. The
[release notes](../../docs/release/v0.6-notes.md) cover the supported ReFL, DRaFT-K and DRTune

combined training implementation at `d605758a` against main. The
[validation evidence](https://github.com/X-GenGroup/Flow-Factory/actions/runs/45119052640) records

The [final #393 gate](https://github.com/X-GenGroup/Flow-Factory/actions/runs/45130111738)
