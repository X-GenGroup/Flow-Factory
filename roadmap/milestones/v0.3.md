# v0.3: developer automation, TP/SP qualification and proportionate validation

This milestone delivers fast developer automation, qualifies merged TP/SP within declared limits,
and a proportionate evidence-driven harness. Shared rationale lives in
[automation design](../design/automation.md) and [validation design](../design/validation.md).
P00 establishes the preceding release baseline. P01a has landed without requiring a GPU runner.
PR #270 is already merged; P03 is a focused qualification/fix follow-up, not its implementation.

<a id="p01"></a>
## P01: establish quality automation and proportionate validation

- **Status:** in_progress
- **Depends on:** none
- **Coordination:** [P01a PR #276](https://github.com/X-GenGroup/Flow-Factory/pull/276); P01b in review; P01c unclaimed

**Outcome.** Contributors get fast automatic feedback, and agents can explain the required
semantic evidence without equating a shared-runtime change with a fixed 32-rank campaign.

**Scope.** P01 is the acceptance boundary for three coherent implementation PRs: P01a supplies
hooks and basic CI, P01b migrates the risk/evidence policy, and P01c adds repository consistency.
Keep these child IDs stable and close the parent only when all three are complete.

**Acceptance.**

- Local and CI checks share authoritative implementations and compatible tool versions.
- Fast checks work without model dependencies or GPU resources; semantic evidence remains
  selected by affected contracts.
- Policy, routes, validators and documentation agree on the replacement gate, with required
  missing evidence reported explicitly.

<a id="p01a"></a>
### P01a: bootstrap fast hooks and matching CPU CI

- **Status:** done
- **Depends on:** none
- **Coordination:** [PR #276](https://github.com/X-GenGroup/Flow-Factory/pull/276)

**Outcome.** A fresh checkout or linked worktree has a documented, lightweight quality workflow
that catches routine problems before review and repeats the same checks on PRs.

**Scope.** Add pinned pre-commit configuration, a small standalone quality environment, shared
check/fix entry points and minimal CPU CI. Retain current Black/isort settings; add syntax,
structured-file, whitespace, merge-marker and artifact checks with appropriate per-hook scopes.
Document bootstrap and server-side required-check setup. Use PR-title validation for the existing
convention; make pre-push optional and keep commits free of GPU/network-service tests.

**Acceptance.**

- A quality-only environment can run the checks without installing the training stack. Warming
  the environment is distinct from measured ordinary commit latency.
- Local and CI scopes match; baseline format debt is visible and has a bounded migration plan.
  Automatic formatting preserves upstream code, prompt fixtures and intentional Markdown breaks.
- Partially staged changes, renamed/deleted files and two linked worktrees behave correctly;
  bootstrap preserves existing hooks and does not alter global Git configuration.
- PR updates automatically receive a stable quality result, even for documentation changes.
  CI reports fixes without committing or pushing them.

Implementation commands and scope: [quality workflow](../../guidance/quality.md), including
[the bounded formatting baseline](../../guidance/quality-baseline.md). PR #276 merged on 2026-11-04
as `b9926146`, with 57 CPU checks, passing Python 3.10/3.12 CI and warm hook timing. The
[main-branch checks](https://github.com/X-GenGroup/Flow-Factory/actions/runs/41804166719) also passed.
P01 remains open until P01b and P01c also satisfy their acceptance criteria.

<a id="p01b"></a>
### P01b: migrate semantic risk and evidence policy

- **Status:** in_progress
- **Depends on:** [P01a](#p01a)
- **Coordination:** implementation on `codex/p01b-validation-policy`; awaiting review and merge

Implementation entry points, observed routing gaps and the review checklist are recorded in
[P01b preparation](../design/validation.md#p01b-implementation-preparation).
The implementation provides [manual validation plans](../../guidance/validation.md), bounded
immutable scope collection, and CPU regressions in the P01a entry point. The historical campaign
manifest and reader remain available unchanged in scope. No production GPU support is added.

**Outcome.** Agents can select and validate a proportionate manual evidence plan before the P04
planner is available.

**Scope.** Update AGENTS, skills, risk rules, test routes, campaign validation and their tests as one
policy migration. Keep impact level, semantic facets, QA evidence type and topology distinct.
Provide a validated manually selected test plan before automated selection exists. Keep previous
campaigns as historical evidence or optional experiments. Scope collection must avoid reading
unrelated checkpoint/binary trees as source text.

**Acceptance.**

- Current policy, executable validation, and agent instructions agree on the replacement gate;
  removing the old gate does not leave required evidence unspecified.
- R4 covers all affected contracts without mandating a fixed job count, reward deployment or GPU
  count. Required missing evidence remains visible as blocked or failed.
- CPU routing regressions distinguish logging-only edits, distributed geometry arithmetic,
  objective-only changes, state changes and harness changes.
- A small explicitly selected test bundle can be validated before P04 is available.

<a id="p01c"></a>
### P01c: enforce focused repository consistency

- **Status:** planned
- **Depends on:** [P01a](#p01a)
- **Coordination:** unclaimed

**Outcome.** Registry, example, documentation and established dependency-boundary drift fails in
an inexpensive reproducible check instead of first appearing in a model-loading or GPU run.

**Scope.** Add import-free built-in registry/recipe reference checks, local documentation and
roadmap validation, and adapters to existing harness/docstring validators. Test established
dependency directions and introduce only demonstrably useful, scoped static/type checks. Reuse
P02's test metadata once available rather than duplicating it in workflow YAML.

**Acceptance.**

- Registry edits and module renames/deletions check affected unchanged examples as well as changed
  files. Aliases, re-exports and external plugin paths have explicit treatment.
- Missing targets, duplicate keys, invalid links and roadmap cycles have focused failing fixtures;
  checks do not require Torch imports, model downloads or an external service.
- Global checks are triggered by their actual inputs and move out of the commit path if their
  measured cost exceeds its budget. They remain enforced by CI.
- Historical debt has a scoped migration and removal condition, rather than a blanket CI skip of
  rules that contributors are required to satisfy locally.

## P02: catalog tests and supply focused GPU fixtures

- **Status:** planned
- **Depends on:** [P01b](#p01b)
- **Coordination:** unclaimed

**Outcome.** Contributors can run a small set of existing or reusable tests that proves a stated
contract on the required backend and topology.

**Scope.** Catalog existing tests before adding overlapping suites. Record coverage, fixture,
backend, mesh, placement, reward mode, oracle and cost. Reuse the existing
[multi-role backend tests](../../tests/distributed/test_multirole_backend.py) and
[controlled overlap tests](../../tests/rewards/test_reward_optimization_overlap.py). Add small
real-model configurations where needed, nonconstant within-group reward fixtures, and a lightweight
service for protocol tests. Introduce only the runner/configuration glue needed to select them.
Include the merged [TP checkpoint tests](../../tests/distributed/test_tensor_parallel_checkpointing.py),
[region-entry parity tests](../../tests/distributed/test_region_entry_parity.py),
[collective settling tests](../../tests/distributed/test_collective_settling.py),
[TP reward agreement tests](../../tests/distributed/test_tensor_parallel_reward_agreement.py) and
[worker-device regression](../../tests/rewards/test_async_reward_worker_device.py). The last case
needs a fresh interpreter and two visible GPUs to detect an unintended GPU-0 context; it does not
need model weights or a distributed backend sweep. Replace fragile wall-clock deadlines in
controlled overlap fixtures with deterministic synchronization where possible.

**Acceptance.**

- Q0-Q3 cases have executable commands and meaningful assertions, with a clear distinction
  between small real model structures and real pretrained-weight checks.
- Distributed cases use the smallest valid topology; two ranks are the default, not a hard cap.
- Numerical cases inspect gradient membership and values or actual updates; role cases inspect
  inactive parameters and populated optimizer state.
- Overlap cases exercise multiple tiles, out-of-order readiness and cleanup without requiring
  a fixed external reward-model deployment.

## P03: qualify the merged TP/SP implementation

- **Status:** planned
- **Depends on:** [P01b](#p01b), [P02](#p02) for final acceptance
- **Coordination:** follow-up unclaimed; implementation merged in [PR #270](https://github.com/X-GenGroup/Flow-Factory/pull/270)

**Outcome.** TP/SP is a supported training capability within an explicit model/layout/backend
matrix. Preserve the implementation merged at `55dcd694`; close the remaining proof and support
documentation gaps in focused follow-up PRs.

**Scope.** Start from [the v0.2 evidence and limitations](v0.2.md#current-capability-boundary).
Preserve the merged LoRA, variant, layout, gradient, peer RNG/reward agreement and collective
cleanup work. Verify the final default/explicit SP behavior per adapter, fail-fast
capability checks, and feature-disabled paths on affected backends. Distinguish supported training,
capacity limits, numerical failures, and unimplemented checkpoint combinations.

**Acceptance.**

- At fixed logical sample/update geometry, compare forward results, every affected parameter's
  gradient, gradient membership and updates against the unsharded reference.
- Exercise LoRA/frozen parameters, multi-role preparation, supported state round trips and
  activation checkpointing. Live resources remain bounded over repeated iterations.
- Reconcile the Qwen-Image-2.1 discrepancy still present in the
  [merged notes](https://github.com/X-GenGroup/Flow-Factory/blob/55dcd69433deb11159d5c03c22689518ce6f315e/.agents/knowledge/topics/tensor_parallel.md)
  with the later PR results. Link a reproducer/fix and revision-specific numerical proof, or
  explicitly exclude the affected configuration from qualified support. Odd-prefix SP rejection
  and capacity OOMs are separate outcomes, not explanations for a numerical discrepancy.
- Reuse existing TP-disabled evidence by exact scope and fill gaps on affected backends. Record
  the identity-seeded offline VAE change: SD3.5 DPO can differ from the pre-TP baseline even with
  TP disabled. Do not promise universal bitwise equivalence to the old process-RNG behavior.
- Publish a user-facing model/layout table separating plan/CPU evidence, real-weight canaries,
  unsupported modes and capacity. Keep FSDP exact-state EMA/reference/snapshot exclusions until
  P07 supplies the missing support. Neither a successful run nor old mislabeled campaign rows
  certify a different model or final revision.

## P04: generate explainable plans and evidence reports

- **Status:** planned
- **Depends on:** [P01b](#p01b), [P02](#p02)
- **Coordination:** unclaimed
- **Release boundary:** `v0.3.0`, after P00-P04 are complete

**Outcome.** A diff produces a reviewable validation plan with reasons, required coverage and
traceable results. P03 and P04 can progress independently after their shared prerequisites.

**Scope.** Connect changed symbols and owner mappings to proof obligations and the test catalog.
Cover mandatory interactions before cost-based selection. Support explicit additions for uncertain
scope. Record source/test/config/dependency identities and avoid treating unavailable hardware as
a passing result. Start evidence reuse with narrowly provable cases, not a general cache system.

**Acceptance.**

- Historical-diff replay catches geometry and shared-state changes while avoiding a backend sweep
  for independent algorithm math or a GPU campaign for harness prose.
- Every selected test has a coverage reason; every required uncovered obligation is reported.
- TP cases from P03 are represented without multiplying every model, algorithm and backend.
- Plans and reports distinguish pass, fail, blocked and not-selected results and remain usable
  by a different agent or contributor.
- CPU selection and the final PR gate consume the same plan as local tooling. Required missing
  GPU evidence cannot pass as an intentionally unselected job, and a new head revision invalidates
  stale evidence unless the documented reuse proof applies.
- The v0.3 release-preparation commit aligns package metadata and changelog with the tag, records
  tested dependency tuples and the qualified support table, and explains v0.2's historical
  source-tag/package-version exception.
