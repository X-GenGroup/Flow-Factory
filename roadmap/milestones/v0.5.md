# v0.5: context parallel training and composition

Build on [v0.4](v0.4.md), initially with FSDP2, ordinary Ulysses CP, and a Wan model. This is a
proposed first integration choice, confirmed by the P06 probe. Additional transports and model
layouts enter stable support only after their own evidence. The target boundary is described in
[architecture direction](../design/architecture.md); test selection follows the harness delivered
by [v0.3](v0.3.md).

<a id="p09"></a>
## P09: deliver the first complete CP training path

- **Status:** in_progress
- **Depends on:** [P08](v0.4.md#p08), with the P05/P06 topology and preparation results
- **Coordination:** `feat/p09-context-parallel`; stacked after merged-baseline qualification
- **Release boundary:** `v0.5.0-alpha.1`

**Outcome.** Wan training runs correctly with CP and TP=1, using a declared supported configuration.

The initial [capability](../../guidance/context_parallel.md) is BF16 SFT with native Ulysses,
FSDP2, full/LoRA tuning and backend recomputation. The public gate rejects TP composition,
evaluation, EMA and exact-state resume. Q2 uses complete tiny native Wan training; pretrained
quality and release tags require their own evidence.

**Scope.** Connect Diffusers' verified CP plan/attention path to FF's mesh and lifecycle. Preserve
global positions, conditions, logical sample/RNG identity and gradient normalization. Initially
restore full denoiser output at the adapter boundary to reuse scheduler and trajectory behavior.

**Acceptance.**

- Compare forward output, elementwise gradients and optimizer updates with CP disabled at fixed
  logical sample/update geometry. Cover the selected precision and activation recomputation.
- Verify attention context, conditioning, token/position order and loss scaling; finite gradients
  alone are insufficient.
- Reject unsupported masks/layouts and dependency combinations early, and document the precise
  experimental capability unlocked by this alpha.

<a id="p10"></a>
## P10: compose TP, SP and CP

- **Status:** planned
- **Depends on:** [P09](#p09)
- **Coordination:** unclaimed
- **Release boundary:** `v0.5.0-alpha.2`

**Outcome.** The first supported model can use TP/SP and CP together with correct training semantics.

**Scope.** Compose FF training-aware TP/SP with the selected CP path. Declare layouts and gradient
obligations at projection, residual, normalization and attention boundaries. Validate head/token
divisibility for the combined layout rather than validating each dimension in isolation.

**Acceptance.**

- Use enough ranks to exercise independent TP and CP axes, plus a direct logical-DP interaction
  case where the affected reduction contract requires it.
- Compare the combination against reference cases with fixed samples and updates, including
  broadcast conditioning, LoRA, frozen parameters and activation recomputation.
- Shared sampling and feedback scopes count each logical sample once. Collectives complete at
  owned boundaries and repeated iterations do not retain unbounded work or tensors.
- Defaults and unsupported combinations remain explicit adapter/backend capabilities.

<a id="p11"></a>
## P11: integrate CP with algorithms and state recovery

- **Status:** planned
- **Depends on:** [P10](#p10)
- **Coordination:** unclaimed

**Outcome.** CP preserves online/offline, multi-role, feedback and checkpoint behavior for the
declared supported paths.

**Scope.** Extend runtime identity and checkpoint metadata for CP; use the state mechanisms from
P07 and lifecycle from P08. Cover representative execution contracts and state types rather than
every algorithm/backend/model product. Checkpoint at a defined drained/safe boundary in the first
implementation; arbitrary in-flight recovery remains a separate feature.

**Acceptance.**

- Representative generation/reward, generation/no-feedback and dataset/no-feedback paths preserve
  sample identities, reward counts, group statistics and optimizer-step geometry.
- Multi-role and reference/EMA/snapshot cases exercise real updates and fixed-topology restore.
- The next update after resume agrees with continuous execution under declared numerical
  tolerances; ready-order execution is preserved or explicitly closed at the save boundary.
- Weight export, restarting on another topology, and exact continuation have distinct documented
  guarantees. An unsupported exact-resume layout fails before state mutation.

<a id="p12"></a>
## P12: validate a second model structure and publish capabilities

- **Status:** planned
- **Depends on:** [P10](#p10); P11 is also required for the beta tag
- **Coordination:** unclaimed
- **Release boundary:** `v0.5.0-beta.1`, after P11 and P12

**Outcome.** CP integration is demonstrated beyond Wan and support is described by actual model
and layout capabilities.

**Scope.** Prefer a Flux-family dual-stream model as the second structure, subject to its actual
upstream plan and adapter requirements. Verify the selected conditioning and stream boundaries.
Make capability declarations usable by both runtime validation and the harness, extending the
existing ownership rather than creating a second conflicting registry.

**Acceptance.**

- The second structure has forward/backward/update evidence and a selected real-weight canary.
- Each declared mode identifies backend, layout, precision/dependency constraints and evidence;
  variable-length, packed, cached-prefix and special-mask paths are either verified or rejected.
- Failures distinguish incorrect numerics, unsupported capability, missing infrastructure and
  capacity. The beta release freezes a concrete supported feature set.

<a id="p13"></a>
## P13: prepare compatibility and release evidence

- **Status:** planned
- **Depends on:** [P11](#p11), [P12](#p12)
- **Coordination:** unclaimed
- **Release boundary:** `v0.5.0-rc.1`

**Outcome.** A user can install, configure, validate, migrate and diagnose the declared CP behavior.

**Scope.** Complete migration notes, examples, checkpoint compatibility, dependency tuples and
capability documentation. Run targeted release qualification through the new harness. Distinguish
activation-memory gains, parameter-memory costs and throughput; parallelism is not a universal
speed claim.

**Acceptance.**

- Related baseline paths on DDP/ZeRO-2/FSDP2 and declared advanced-parallel configurations have
  sufficient evidence, including selected actual weights and relevant cross-machine placement.
- Selection covers known critical interactions and explains exclusions; it is not a mandatory
  full Cartesian product or fixed reward deployment.
- Necessary incompatible public changes have migration instructions; performance claims include
  workload and environment. Dependency boundaries are tested rather than inferred from minima.
- The RC commit, version metadata, artifact identities and documentation agree.

## P14: release v0.5

- **Status:** planned
- **Depends on:** [P13](#p13)
- **Coordination:** unclaimed
- **Release boundary:** `v0.5.0`

**Outcome.** TP/SP/CP and the proportionate harness are stable capabilities within the published
support boundaries.

**Scope.** Fix RC findings, complete release notes and version metadata, and validate the final
integration commit. New features discovered during stabilization move to a later item.

**Acceptance.**

- No required correctness or compatibility evidence remains failed or unexplained.

  continuation and repeated-iteration cleanup where relevant.
