# v0.5: model and algorithm coverage for TP, CP and their composition

Build on [v0.4](v0.4.md), initially with FSDP2, ordinary Ulysses CP, and a Wan model. This is a
proposed first integration choice, confirmed by the P06 probe. Additional transports and model
layouts enter stable support only after their own evidence. The target boundary is described in
[architecture direction](../design/architecture.md); test selection follows the harness delivered
by [v0.3](v0.3.md).

### P11g: compose context parallelism with reward overlap

- **Status:** done
- **Depends on:** [P11f](#p11f), [P11l](#p11l)
- **Coordination:** [PR #305](https://github.com/X-GenGroup/Flow-Factory/pull/305), qualified at `064f8b8d`, merged as `f7fe88af`; A–C and selected evidence complete

**Scope and acceptance.** Qualify ordered and ready tile execution, slow/failed rewards, identical rank choices, accumulation and role windows, cancellation and repeated cleanup. Save only at drained boundaries; preserve scheduling mode in runtime identity. Overlap is inapplicable to reward-free algorithms.

**Asynchronous numerical acceptance (user decision, 2026-11-06).** Different reward completion
orders and floating-point gradient accumulation orders are acceptable. Within a fixed optimizer
step, compare the same sample multiset, weights and parameter state with numerical tolerances;
do not require bitwise equality across schedules. Preserve exactly-once sample consumption,
accumulation boundaries, role cadence and strict same-policy rollout/replay. Ready-mode resume
must restore the saved state correctly and continue valid training; it need not reproduce a future
asynchronous completion schedule or an identical trajectory.

Changing which samples cross an optimizer-step boundary changes update semantics as well as
roundoff. Record and test that scheduling behavior explicitly instead of attributing every drift
to addition order. Collective ordering, rank agreement, error propagation and cleanup remain hard
correctness requirements; retain the late-future-failure regression when opening the CP overlap gate.

**Confirmed correctness finding and correction (2026-11-06).** A reward future can fail after
readiness: one rank enters the WORLD error guard while a peer enters CP sharing. The merged
implementation orders local preparation -> WORLD error guard -> peer sharing, with CPU/Gloo regression
evidence and independent review. This fixes a collective-order race, independently of the accepted
floating accumulation variation. The complete-loop increment adds nine passing Gloo cases with
52 actual worker processes, 217 focused CPU tests and 10 selection regressions. These fixtures
retain the real feedback lifecycle with planned samples and an optimizer observer; they do not
qualify native model training. The final #305 implementation enables CP overlap and adds A–C with real
Wan training: full ordered DP2/CP2, LoRA ready DP2/TP2/CP2, and full ready DP4/CP2 with two R2
subgroups and weighted sources. All three scenarios passed final qualification at `064f8b8d`.
Their immutable-source proof includes actual pending futures during updates, first-policy replay,
complete GAS windows, late-future failure after an update, cleanup, drained evaluation/save and fresh-process resume.
The merged PR publishes all 28 selected cases / 1,148 pytest executions plus consistency and
passing CI. Pure admission selection is bounded to CPU contracts and these new native paths, while
capability/backend/normalization and concrete state owners retain their affected native proofs.
