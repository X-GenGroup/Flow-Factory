# v0.5: model and algorithm coverage for TP, CP and their composition

Build on [v0.4](v0.4.md), initially with FSDP2, ordinary Ulysses CP, and a Wan model. This is a
proposed first integration choice, confirmed by the P06 probe. Additional transports and model
layouts enter stable support only after their own evidence. The target boundary is described in
[architecture direction](../design/architecture.md); test selection follows the harness delivered
by [v0.3](v0.3.md).

### P12j: materialize FSDP2 target roots directly in their prepared layout

- **Status:** planned
- **Depends on:** [P12i](#p12i); the canonical packed-TP owner ([#347](https://github.com/X-GenGroup/Flow-Factory/pull/347)) and the parallelism refactor [#357](https://github.com/X-GenGroup/Flow-Factory/pull/357) for the TP style surface
- **Coordination:** native stack starting at [#356](https://github.com/X-GenGroup/Flow-Factory/pull/356); implementation PRs are linked in this stack
- **Release boundary:** `v0.5.0-beta.1`; part of the frozen beta scope by user decision on 2026-11-08

**Problem record.** Every rank loads each target root in full on CPU, and only then applies TP and
FSDP2. Released H3 Ref2VA has 33.12B FP32 original parameters, so each process holds about 133 GB
of host memory. TP then broadcasts every parameter from TP rank 0, although each rank already holds
it. With CPU-RAM-efficient loading off, Accelerate 1.15 keeps an unused `original_sd` alive during
`fully_shard` ([accelerate#4511](https://github.com/huggingface/accelerate/issues/4511)). The
initialization peak is therefore the TP-local root plus every new shard. At main `dc17e8f6`:

- TP2 leaves 61.9 GiB resident before FSDP2.
- DP4×TP2 peaks at 77.26 GiB. #356 releases the retained allocator cache, so the first step can run.
- DP2×TP2 exhausts 79.19 GiB devices.
- A development Accelerate patch that only captures `original_sd` for efficient loading lowers the
  DP2×TP2 peak to 62.09 GiB, and one bounded LoRA step passes at 43.89 GiB. This is not a supported
  configuration.

Accelerate's efficient loading broadcasts rank 0's full tensors and cannot follow an earlier TP
transform. The trainer rejects that combination, and a canary that bypasses the trainer hangs on
mismatched collectives. Together these are the reproducible limitations that
[architecture direction](../design/architecture.md#ownership-and-upstream-reuse) requires before
Flow-Factory takes over target materialization.

**Outcome.** A declared FSDP2 target root keeps its loaded values as a host-side source and moves
its parameters to the meta device. Variants, LoRA, precision, TP/SP, CP and FSDP2 then produce the
final layout on meta. Only after that does each rank allocate its final local shards and fill them
from the source. The GPU initialization peak stays near the final sharded state plus one
module-sized transient, at any DP degree. TP no longer broadcasts loaded weights. TP composes with
CPU-RAM-efficient loading. A later stage reads checkpoint slices directly, so host memory no longer
holds one full replica per rank.

**Scope.**

- `ModelPreparation` owns the new phase. After variant materialization and initial-state
  synchronization, it records each unique target parameter's value and moves only the parameters to
  the meta device. Buffers stay real, so native non-persistent tables remain computed by their
  modules. Auxiliary, host and reward resources keep replicated loading (constraint 19).
- TP/SP plans, CP hooks and Accelerate's FSDP2 preparation run unchanged on the meta bundle. TP on
  meta tensors slices locally without a source-rank broadcast. Accelerate remains the owner of
  wrapping, activation checkpointing and the optimizer remap. Because the bundle is meta,
  #4511 cannot retain device memory.
- Materialization reuses the applied TP style for each module. It distributes the recorded source
  one module at a time without communication, then takes the same FSDP2 dim-0 chunk that
  `fully_shard` would take. Packed and canonical-permutation styles therefore keep their own
  partitioning, and parity with the replicated path holds by construction. An unrecognized style,
  a missing source or an unsupported placement fails before any rank allocates device memory.
- LoRA and other newly created parameters are initialized from `(seed, canonical parameter name)`
  before sharding, replacing rank-0 initialization plus broadcast. The runtime identity records
  the new initialization version. Exact resume from an older identity fails before state mutation
  with a concrete message (user decision on 2026-11-08).
- An adapter capability opts in per model. DDP, ZeRO-2 and undeclared adapters keep replicated
  loading. Once an adapter is qualified, TP with `cpu_ram_efficient_loading` selects this path
  instead of failing.
- A later stage replaces the host-side source with lazy safetensors slices and meta construction of
  target roots, then records load time and host RSS.

**Acceptance.**

- For every adopting registry identifier and layout already qualified in P12, each rank's local
  shards, buffers and optimizer-visible parameter identities equal the replicated path bitwise at a
  fixed seed. Coverage includes full/LoRA, frozen siblings, named variants, packed TP and SP/CP on
  and off. Same-state forward and gradient checks reuse the P12 fixtures.
- Exact resume, weight-only resume and EMA/reference/snapshot creation work after sharded
  materialization, and older initialization identities fail before mutation.
- Released H3 Ref2VA records the initialization peak, step peak, host RSS and wall-clock load time
  for DP2×TP2, DP4×TP2 and TP1×DP8 on an unpatched Accelerate, next to the replicated baselines.
- No throughput or convergence claim. Load-time figures state their storage and topology.

**Open decisions.**

- Whether FSDP2's `to_empty` preserves the parameter identities that Accelerate remapped into the
  optimizer, or whether materialization must rebind the optimizer. The first probe decides.
- Whether Diffusers CP hooks can be installed on meta modules or must follow materialization.
- When to remove #356's preparation-cache release: after the minimum supported Accelerate includes
  the #4511 fix, or once every FSDP2 adapter uses this path.

**Delivery.** #356 fixes the replicated path. A roadmap PR records this item. Then, in order: a
probe with materialization primitives and tiny-model parity and no behavior change; the main path
on dense layouts (Wan, SD3.5); adoption per model structure in P12 batch order; the
checkpoint-slice stage; and the H3 canaries with capability documentation.
