## Implemented ownership changes

- P11d1: Wan declares `required_precision_policy`; the shared CP preflight requires the existing
  `cross_attention_fp32_v1` policy for CP-only and TP+CP. Precision implementation and optimizer
  mathematics are unchanged. The capability identity changes: do not promise exact-state
  compatibility with checkpoints carrying the previous CP capability identity.
- P11e: `BaseTrainer.evaluate` owns valid-row filtering after symmetric padded model forwards.
  `EvaluationBatchPlan` validates standard sequential loader geometry. Reward buffers receive
  only real rows, including empty replicas. Five FP64 summary values per reward/replica are
  gathered over logical DP and merged in fixed rank order. Explicit seed zero is honored;
  EMA and buffer cleanup remain exception-safe. Active evaluation records
  `sample_ownership=logical_dp_unpadded_v1`; incompatible exact resumes fail early.
- P11f: `GroupCoordinator` partitions each logical-DP rank list at fixed TP/CP coordinates.
  Every physical rank creates groups in the same order. One-replica groups need no collective;
  a subgroup spanning all DP replicas reuses the existing group. No objective, sampler ordering,
  gradient reduction or GRPO replay calculation changes.

These shared owners follow the [ub-mode design direction](https://github.com/unclebob/ub-mode):
keep boundaries small and explicit, fix the authoritative owner and avoid per-algorithm patches.

## Next implementation boundary

P11g is planned only. The existing trainer already synchronizes integer readiness/error flags
and tile choices across all physical ranks so FSDP peers enter the same optimization. Reward
payloads/statistics have a separate logical-DP owner. First test whether these owners suffice
before adding another scheduler, wrapper or process group.

1. Add failing admission tests for CP GRPO overlap while retaining existing unsupported
   algorithm/reward/layout gates. Remove only the blanket CP gate after runtime evidence.
2. Test ordered and ready scheduling with Gloo TP/CP/DP, asymmetric completion, exact sample IDs,
   cancellation and one-rank reward failure; all model peers must select identical work.
3. Qualify native full/LoRA CP and TP+CP with multiple group-complete tiles per acquisition,
   strict same-policy replay before updates, optimizer oracles and genuine reward/optimization
   overlap events. Controlled delays prove ordering, not performance.
4. Compose train → drain → EMA eval → exact save → fresh-process restore → next acquisition.
   Ordered mode compares continuation exactly. Ready mode records actual work order and checks
   state/sample/replay semantics without claiming equality under different completion orders.

Then continue P11h (Offline DPO, GRPO-Guard, DPPO), P11i (NFT, AWM, DGPO, online DPO, CRD),
P11j (DiffusionOPD, TDM, TDM-R1), P12 model/algorithm coverage, P13 cross-node/performance and
P14 release qualification. Keep precision, loader, state and collective logic in shared owners;
introduce model declarations only where a real second structure requires them. Preserve the
user's GRPO train/inference consistency requirement when choosing efficient reduction order.
