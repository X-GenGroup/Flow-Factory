## What the evidence proves

The two-GPU native controls compare outputs, all active parameter/input derivatives, repeated
optimizer updates/moments and canonical weight reload. Local token-shape observations establish
that the intended residuals stay sharded. Full/LoRA and checkpointed variants are chosen where
the layout or gradient owner differs. Refiner and text probes record finite nonzero gradients at
every step instead of treating the mere presence of a gradient tensor as learning.

The selected eight-GPU controls exercise DP2 × TP2 × CP2 with native FSDP2 preparation and three
updates. Distinct cases cover packed final role norms, prefix/cached queries, the pointwise output
head, reference-image ordering, odd text and real attention head geometry. Missing-CP-factor and
receipt-corruption controls prevent finite-but-wrong reductions from being accepted.

Broader unchanged lifecycle and algorithm evidence is retained at its original sources through
reviewed incremental acceptance. The ordinary all-current-source report remains distinct from
`accepted_incremental`. Each acceptance keeps complete source deltas and baseline artifact
identity; compression changes transport size only. Selected CPU cases and newly required GPU
contracts must pass at their final source. No historical execution is renamed to a new head.

## Preserved numerical and compatibility decisions

- Z-Image's native zero-padding FP32 near-zero discrepancy is retained as a failure in the
  investigation. The FP64 zero-padding control and bounded learned-padding FP32 fixture pass
  their original elementwise gates; the implementation does not silently widen those gates.
- Qwen CUDA forward uses an independent FP64 native-rounding envelope. Gradient, optimizer and
  state tolerances remain unchanged. The earlier failing forward candidate is retained.
- Bagel comparisons preserve packed sample membership. Per-sample execution is not a valid
  replacement reference for a model without batch invariance.
- TP state now fingerprints prepared placements; old TP optimizer-state identities require
  explicit migration or a model-only restart. Canonical model weights retain their names/shapes.
- New local-row observations are not new peak-memory, throughput or convergence measurements.
  Existing numerical and capacity records retain their tested dependency tuples and scope.

## Reading and release work

Users start at [parallel training](../../guidance/parallelism/README.md), including the model,
algorithm, configuration and performance pages. Contributors use the
[implementation reference](../../docs/reference/parallelism/README.md). Agents load the
[parallelism support router](../../.agents/knowledge/topics/parallelism_support.md) and generate
validation plans from the actual diff. Historical investigations are kept out of startup context.

After implementation review and merge, [P13/P14](../milestones/v0.5.md#p13) complete dependency,
installation, migration and final artifact checks, then version metadata, tags and the release
image. See the [release checklist](../../docs/release/v0.5.md). EP, topology-changing optimizer
continuation, arbitrary in-flight recovery and model-admitted Ring remain later work. PR #304 is
independent of this stack.
